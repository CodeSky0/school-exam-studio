# School Exam Studio Web UI 与动效优化设计

日期：2026-11-14
状态：已确认
基线：`f2ae211`

## 1. 目标与边界

在保留现有业务、数据与打印契约的前提下，统一优化公共页面、认证页面、管理员工作台和教师工作台的视觉、交互、响应式与动效。设计方向为“暖纸感 + 深玫瑰”，延续当前 Yohaku 气质，解决旧规格中的学术蓝与现行实现不一致的问题；本次以现行暖中性色体系为准。

采用“交互动效增强”方案：新增 `framer-motion`，重点改善组卷购物车、题目与试卷列表、筛选结果和详情展开反馈，不进行大幅品牌化重塑。

本轮明确不改变：

- Go 后端、API 路径、请求与响应契约、权限和学校数据隔离。
- TanStack Query、Zustand、TipTap、KaTeX、OCR、CSV 导入及组卷保存逻辑。
- 真实数据来源，不添加演示数据或静态业务数字。
- A4 纸张尺寸、分页、打印边距、打印时隐藏应用 UI 及 PDF 输出契约。

## 2. 视觉系统

### 2.1 色彩与材质

- 页面以暖纸色和石灰中性色构成基础层级，浅色页面底色为 `#f7f5f2`，主文字色为 `#292624`，不使用纯黑。
- 浅色主题主强调色为 `#9f4256`，hover 使用 `#87384a`；主按钮白字和普通强调小字必须达到 WCAG AA 对比度。
- 成功、警告、错误状态同时调整前景与浅底色，不能仅依靠颜色传达状态。
- 深色主题使用同一中性色与玫瑰色语义映射，不引入紫蓝霓虹、外发光或高饱和渐变。
- 边框、内高光和带背景色的柔和阴影用于表达层级；只有需要浮层或功能分组的区域使用卡片，统计与导航优先使用分隔线和留白。

### 2.2 字体与排版

- 使用 Next.js 字体能力加载 Geist，中文使用系统无衬线字体回退，数字和需要精确比较的数据使用等宽字体。
- 工作台不再使用宋体标题；通过字重、字号、行高、字距和颜色建立层级。
- 正文保持可读行宽，辅助文字不小于现有可读性底线；桌面维持高密度，窄屏增大辅助文字与触控目标。
- 所有现有及新增界面文案保持简体中文。

### 2.3 页面与布局

- 首页采用左侧文案与操作、右侧试卷预览的非对称首屏，不使用居中超大标题或通用三列营销卡片。移动端回退为单列。
- 登录、注册和初始化页保留双栏结构，强化品牌侧与表单侧的层级和完成状态反馈。
- 后台保留 240px 桌面侧栏与高密度内容区，统一页面标题、描述、操作区、筛选区和内容区间距。
- 仪表盘使用真实数据构成清晰的信息层级，避免无功能的装饰卡片。
- 题库、试卷和教师管理在桌面保留表格；窄屏使用摘要、可展开详情和直接可见的主要操作，避免依赖超宽横向滚动。
- A4 屏幕预览保持完整纸张比例，缩放或横向浏览只影响屏幕，不修改打印画布。

## 3. 动效系统

### 3.1 技术约束

- 仅新增 `framer-motion` 动画依赖，继续统一使用 `@radix-ui/react-icons`，不引入第二套图标或组件库。
- 页面和静态布局继续保持 Server Components；交互动画放入独立的 Client Component 叶子节点。
- 在现有客户端 Provider 中通过 `MotionConfig reducedMotion="user"` 遵循系统减少动态效果设置。
- 持续动画只用于少量同步或活动状态指示，并隔离在 memoized 小组件中；不添加无功能的粒子、滚动劫持或大幅背景运动。
- 动画仅使用 `transform` 和 `opacity`；连续指针动画若出现，只使用 motion values，不能通过 React 逐帧状态更新实现。

### 3.2 关键反馈

- 组卷购物车的添加、删除、上下移动和拖拽排序使用 `layout`、`AnimatePresence` 与弹簧过渡，保持操作焦点和阅读顺序可追踪。
- 题目、试卷及筛选结果更新使用克制的交错进入与布局过渡；分页或筛选变化不造成整页闪烁。
- 题目展开、移动导航、Dialog、ConfirmDialog 和状态消息使用约 160–240ms 的淡入与短位移；需要退出的组件必须等待退出完成再卸载。
- 按钮、可点击记录和控件提供 hover、active、focus-visible、disabled 状态；触控反馈不依赖 hover。
- 加载时使用匹配实际布局的骨架，不用无限旋转指示器替代内容结构；动画不能掩盖请求错误或制造成功假象。

## 4. 核心 UX 与可访问性

### 4.1 应用壳与导航

- 增加“跳到主内容”链接和明确的主内容焦点目标。
- 移动导航打开后，将焦点移入导航、限制背景可交互性并锁定背景滚动；Escape、遮罩和关闭按钮均可关闭。
- 关闭后焦点归还菜单触发按钮；导航具备合适的对话框语义、可访问名称和 `aria-expanded` 状态。

### 4.2 弹窗与列表

- ConfirmDialog 使用 React `useId` 生成唯一标题与描述 ID，修复同页多个确认框的无障碍引用冲突。
- 桌面表格保留现有键盘可聚焦滚动区域；移动摘要记录仍提供完整字段、状态和操作，不丢失权限相关功能。
- 拖拽排序继续保留上移、下移按钮；动画重排不能成为理解顺序的唯一方式。

### 4.3 筛选与表单

- 管理员工题库创建人筛选继续使用原 `creator_id` 查询参数，但界面复用现有教师列表数据提供姓名选择，不再要求管理员手工复制 UUID。
- 教师数据请求失败时显示行内错误并保留重试能力，不能退化为伪造教师选项。
- 表单标签、辅助说明、错误说明和焦点顺序保持现有语义；校验错误继续通过行内文本和 `role="alert"` 表达。
- 空状态说明可执行的下一步，加载、空、错误和成功状态均有完整视觉样式。

## 5. 组件与数据流

- 在现有 `Providers` 中组合 MotionConfig，不新增全局业务状态。
- 动画封装围绕现有 `QuestionTable`、`PaperList`、`PaperCart`、`Dialog` 和应用壳进行，避免把整个页面转为 Client Component。
- 列表动画直接响应已有 Query 数据或 Zustand 购物车状态；请求、缓存、失效、权限判断和保存顺序保持原实现。
- 教师姓名选择仅在管理员题库筛选中复用已有教师 API，选中后仍序列化为 UUID；后端无需变更。
- 视觉样式优先通过 Tailwind v4 语义令牌和现有 UI 原语扩展，打印相关覆盖限定在屏幕媒体或屏幕预览容器。

## 6. 验证与验收

### 6.1 静态与构建检查

在 `frontend/` 执行：

- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`

### 6.2 浏览器与端到端检查

- 覆盖首页、登录或注册、管理员仪表盘与题库、教师题库与组卷、个人中心等主要页面。
- 检查桌面与约 390px 移动视口，确认无意外横向溢出、主要操作可见、触控目标可用。
- 检查键盘打开与关闭移动导航后的焦点位置、弹窗可访问名称、跳到主内容链接及列表非拖拽排序。
- 检查深色模式、系统 reduced-motion、加载、空数据和请求错误状态。
- 在环境允许时运行现有 Playwright E2E，并保留 A4 页面尺寸、打印 UI 隐藏和分页断言。
- 不以后端或 OCR 不可达为由伪造成功状态；受环境阻塞的验证必须明确记录。

# School Exam Studio AI 深度融合与校内 AI Agent 计划

日期：2026-11-15
状态：实施中
目标分支：`main`

## 1. 目标

把 AI 从“一个附加按钮”变成题库系统的**一等能力**，并最终形成校内的 **AI Agent**：教师或管理员用自然语言描述目标，Agent 自己规划并执行录题、打标、分类、补解析、出变式、题库体检、组卷等操作，把重复劳动交给系统，把最终审核权留给教师。

本计划的硬约束：

1. **不牺牲现有工程质量**：PostgreSQL 仍是唯一业务事实存储；权限、租户隔离、审核流程不变。
2. **AI 永远可降级**：未配置模型密钥时，系统使用确定性本地引擎，功能可用但明确标注“本地模式”，不伪装成大模型结果。
3. **AI 不直接改动已发布内容**：自动修改只发生在草稿；发布、归档、删除、改密码等高风险操作永远需要人工。
4. **所有 AI 行为可审计、可回滚**：每次 Agent 运行、每个被修改的题目都留下记录。
5. **生成内容必须可识别**：AI 生成的题目、标签、解析带元数据与“待人工复核”标记。

## 2. 现状与差距

现有系统已具备：学校初始化、JWT 权限、题目 CRUD、审核状态机、富文本/LaTeX、OCR、CSV 导入、组卷、A4 打印、教师管理与真实数据库测试。

缺口：

- 题目只有自由标签，没有知识点、分类与 AI 元数据。
- 没有模型调用层，也不存在离线可用的智能能力。
- 题库质量只能靠人肉逐题检查，缺重复题检测、缺解析检测、难度与知识点分布分析。
- 没有自然语言操作入口，教师仍需逐页点击完成批量工作。
- 没有 AI 行为审计与结果复核机制。

## 3. AI 能力全景（头脑风暴）

### 3.1 本次落地

| 能力 | 说明 | 入口 |
|---|---|---|
| 题目智能分析 | 识别学科、年级、题型、难度、分类、知识点、标签，校对答案，生成解析 | 编辑器 AI 助手 / 题目分析接口 |
| 答案与解析生成 | 基于题干与选项生成参考答案候选与分步解析；已有内容默认不覆盖 | 编辑器、Agent |
| 题目变式生成 | 换数、换情境、逆向提问、难度升降，保留知识点与题型结构；可批量落为草稿 | 题目详情 / Agent |
| 知识点驱动出题 | 按知识点、标签、分类、年级、题型、难度生成新题草稿 | AI 工作台 / Agent |
| 题库体检 | 缺失答案/解析/知识点/分类、重复题、标签孤岛、难度分布、学科年级异常 | AI 工作台 / 管理端 |
| 自动整理题库 | 批量补标签、分类、知识点，批量补解析，只处理草稿 | Agent |
| 智能组卷 | 按学科、年级、知识点、难度分布从已发布题目中选题，生成试卷草稿 | Agent |
| AI Agent | 自然语言目标 → 计划 → 工具调用 → 结果与审计 | `/teacher/ai`、`/admin/ai` |

### 3.2 后续路线（本次预留模型与接口，不强行上线）

- OCR + AI 一步结构化录题（识别后直接给出题型、选项、答案草稿）。
- 语义相似题推荐与组卷去重（向量检索）。
- 学情分析：按班级/知识点统计得分率、错题归因与补偿练习。
- 题目质量评分与发布前 AI 质检报告。
- 多模型路由、成本预算、提示词版本管理与 A/B 评测。
- 知识点图谱与先修关系维护。

```text
└───────────────────────────────────┬────────────────────────────────────────┘

┌───────────────────────────────────▼────────────────────────────────────────┐
│ Backend (Go / Echo)                                                        │
│  internal/ai                                                               │
│   ├─ engine.go      分析 / 变式 / 出题 / 体检 领域服务                     │
│   ├─ llm.go         OpenAI 兼容 Chat Completions 客户端                    │
│   ├─ local.go       确定性本地引擎（无密钥可用，可测试）                    │
│   ├─ prompt.go      提示词与 JSON 契约                                      │

│   └─ handler.go     HTTP 接口                                               │
│  internal/question  题目领域 + AI 元数据应用 + 题库快照                    │
│  internal/paper     组卷（Agent 智能组卷复用）                              │

                                    │

                          Redis（限流，可选 AI 配额）
```

### 4.1 模型接入策略

- 统一走 **OpenAI 兼容** `POST {AI_BASE_URL}/chat/completions`，可接 OpenAI、DeepSeek、通义、Moonshot、本地 vLLM/Ollama 等。
- 环境变量：
  - `AI_BASE_URL`：例如 `https://api.deepseek.com/v1`
  - `AI_API_KEY`
  - `AI_MODEL`：例如 `deepseek-chat`
  - `AI_TIMEOUT_SECONDS`：默认 45
- 未配置 `AI_BASE_URL` 或 `AI_API_KEY` 时，自动使用 **本地引擎**。
- 大模型调用失败、超时、返回非 JSON 时，同一请求自动降级到本地引擎，并在响应中标记 `provider=local_fallback` 与告警。
- 响应中的 `provider`、`model`、`confidence` 会随题目元数据持久化，避免“AI 结果不可追溯”。

### 4.2 为什么保留本地引擎

1. 测试必须离线、确定性、可重复。
2. 学校内网可能没有外网模型。
3. 大模型不可用时，教师仍能做基础的标签补全、解析补全和题库体检。
4. 本地引擎的结果明确标注置信度较低，并强制人工复核。

## 5. 数据设计

### 5.1 `questions` 扩展字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `category` | `varchar(60) not null default ''` | 题目分类，如“数与代数”“文言文阅读” |
| `knowledge_points` | `jsonb not null default '[]'` | 结构化知识点，与自由标签分离 |
| `ai_generated` | `boolean not null default false` | 是否由 AI 生成 |
| `ai_meta` | `jsonb not null default '{}'` | provider、model、confidence、analyzed_at、review_required、rationale |
| `content_hash` | `varchar(64) not null default ''` | 归一化题干哈希，用于重复题检测 |
| `source_question_id` | `uuid null` | 变式题来源，保留血缘 |

新增索引：

- `questions_knowledge_points_gin`：知识点筛选。
- `(school_id, category)`：分类统计。
- `(school_id, content_hash)`：重复题快速定位。

兼容策略：全部字段带默认值，旧数据零迁移风险；`content_hash` 在题目创建/更新时计算，题库体检对旧数据在内存中补算。

### 5.2 `ai_runs`（Agent 运行记录）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | 运行 ID |
| `school_id` / `creator_id` | uuid | 租户与发起人 |
| `goal` | text | 用户原始目标 |
| `intent` | varchar(40) | 识别出的意图 |
| `status` | varchar(20) | `succeeded` / `failed` |
| `provider` / `model` | varchar | 实际使用的引擎 |
| `plan` | jsonb | 计划步骤 |
| `steps` | jsonb | 每步状态、摘要、影响对象 |
| `result` | jsonb | 汇总结果与产物链接 |
| `error` | text | 失败原因（不含密钥） |

索引：`(school_id, creator_id, created_at desc)`、`(school_id, status)`。

### 5.3 `ai_audit_logs`（变更审计）

记录每次 AI 写操作：运行 ID、操作者、动作、目标类型/ID、变更详情、时间。教师只能看自己的记录；管理员可看全校。

## 6. 后端设计

### 6.1 领域类型

```go
type Analysis struct {
    Subject, Grade, QuestionType, Category string
    Difficulty int
    Tags, KnowledgePoints []string
    Answer, Explanation string
    Confidence float64
    Provider, Model string
    Warnings []string
}
```

分析、变式、出题、体检均以纯数据结构进出，Handler 不包含提示词或业务规则。

### 6.2 本地引擎规则（可测试）

- 学科：优先沿用教师学科；否则按公式/符号/关键词（函数、方程、古诗、English、力、化学式等）推断。
- 年级：从“一年级…高三”“七年级/初二”等文本提取。
- 难度：结合题干长度、公式密度、题型、关键词（证明、综合、应用、计算）映射 1–5。
- 分类：按学科关键词映射到稳定分类集合，未知归为“综合应用”。
- 知识点：从题干、答案、标签中匹配知识点词典，去重并限制数量。
- 标签：知识点 + 题型 + 难度 + 分类，最多 10 个。
- 答案：已有答案保留；缺答案时**不臆造选择题答案**，返回空值 + 告警。
- 解析：生成“考查点 → 已知条件 → 推理/计算 → 结论”的结构化模板；已有解析默认不覆盖。

### 6.3 大模型契约

- 所有提示词要求**只输出 JSON**，服务端做二次校验、长度限制、富文本消毒。
- 单次分析题干上限 20,000 字符；变式/出题数量 1–10。
- 模型返回的标签、知识点、分类、难度越界时丢弃并降级。
- 不使用用户输入拼接 URL；Base URL 只来自服务端配置。
- 日志只记录 provider、model、耗时、request_id，不记录题干全文、密钥与 Authorization。

### 6.4 HTTP 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/ai/status` | 登录 | 当前引擎、模型、能力开关、限制 |
| POST | `/ai/analyze` | 教师/管理员 | 分析未保存草稿，不写库 |
| POST | `/ai/questions/:id/analyze` | 教师/管理员 | 分析已有题目；`apply=true` 时写回草稿 |
| POST | `/ai/questions/:id/variants` | 教师/管理员 | 生成变式；`persist=true` 时批量创建草稿 |
| POST | `/ai/generate` | 教师/管理员 | 按知识点/标签/分类出题；可落草稿 |
| GET | `/ai/bank/audit` | 教师/管理员 | 题库体检；教师只统计可见题目 |
| POST | `/ai/agent/runs` | 教师/管理员 | 提交自然语言目标并执行 Agent |
| GET | `/ai/agent/runs` | 教师/管理员 | 自己的运行记录；管理员可看全校 |
| GET | `/ai/agent/runs/:id` | 发起人/管理员 | 运行详情、步骤、结果 |
| GET | `/ai/audit-logs` | 管理员 | 全校 AI 变更审计 |

写操作规则：

- `apply` / `persist` 只能作用于 **draft**；教师只能操作自己的草稿，管理员可操作本校草稿。
- 已发布/归档题目只读分析，不自动修改。
- 创建题目仍走既有 `question` 领域校验、消毒、权限与学科约束。

### 6.5 Agent 设计

**意图识别（确定性优先）**

| 意图 | 触发词示例 | 工具 |
|---|---|---|
| `audit_bank` | 体检、检查、质量、重复、统计 | 题库体检 |
| `tag_questions` | 打标签、分类、知识点、整理 | 批量分析 + 应用元数据 |
| `fill_explanations` | 补解析、生成答案、补全 | 批量分析 + 应用解析 |
| `generate_variants` | 变式、改编、类似题 | 变式生成 |
| `generate_questions` | 出题、生成题目、新题 | 知识点出题 |
| `compose_paper` | 组卷、出一份试卷 | 选题 + 组卷 |
| `analyze_question` | 分析这道题 | 单题分析 |

参数提取：学科、年级、数量（“5 道”）、知识点（引号/书名号/词典）、题目 ID、难度、分类。

**执行流程**

1. 解析目标，生成人类可读计划（3–5 步）。
2. 查询作用域内题目快照（教师：自己的+已发布可见；管理员：全校）。
3. 调用工具执行，逐步记录状态、摘要、影响数量与 ID。
4. 失败可继续的步骤记录告警，不可继续则整体失败。
5. 写入 `ai_runs` 与 `ai_audit_logs`，返回计划、步骤、产物链接。

**安全边界**

- 不提供“发布”“删除”“改密码”“禁用教师”工具。
- 所有批量写操作有单次上限（默认 20 道），避免一次误改整库。
- 生成题目一律为草稿，`ai_generated=true`、`review_required=true`。
- 变更前读取、变更后复核；只更新明确目标字段。
- 运行记录与审计日志保留变更摘要，支持人工追溯。

## 7. 前端设计

### 7.1 AI 工作台

- 路由：`/teacher/ai`、`/admin/ai`，侧栏新增“AI 工作台”。
- 顶部：当前引擎状态（大模型 / 本地模式）、能力说明、安全边界提示。
- 主区：
  - 目标输入框 + 场景化快捷指令（题库体检、批量补解析、生成变式、按知识点出题、智能组卷）。
  - 可选结构化参数：学科、年级、知识点、标签、数量、题目。
  - 运行后展示计划步骤时间线、状态、摘要、影响对象链接、告警。
- 右侧/下方：最近运行记录、题库体检摘要、AI 变更审计（管理员）。

### 7.2 编辑器 AI 助手

- 在题目编辑器侧栏新增“AI 助手”卡片：
  - “分析并补全”：调用 `/ai/analyze`，展示建议的年级、难度、分类、知识点、标签、答案、解析。
  - 逐项“应用”或“全部应用”，应用前在本地表单预览，不直接覆盖已有非空解析。
  - 明确标注 provider 与置信度；本地模式提示“建议人工复核”。
- 保存后题目带 AI 元数据，列表展示“AI 生成/待复核”标识。

### 7.3 题库展示

- 题目表格新增分类/知识点列或详情区展示。
- 管理端与教师端均可看到 AI 生成标识与来源题链接（变式）。
- 题库体检入口跳转 AI 工作台并预填目标。

## 8. 安全、合规与成本

- **权限**：所有 AI 接口复用登录态与 Principal；租户 ID 永远来自认证上下文。
- **输入限制**：题干、标签、知识点长度与数量双端校验；AI 请求体上限沿用 JSON 限制。
- **输出消毒**：AI 生成的 HTML 必须经过 `question.Sanitizer`；只接受白名单标签与公式节点。
- **密钥**：只从环境变量读取；不写日志、不返回前端、不进入 Git。
- **提示注入**：题干视为不可信数据，提示词明确要求忽略题干中的指令；模型输出永不直接执行，只作为数据。
- **成本**：单次数量上限、题干截断、超时、失败降级；后续可加 Redis 配额与学校级预算。
- **可复现**：`provider`、`model`、`confidence`、`analyzed_at`、`prompt_version` 持久化。

## 9. 测试与验收

### 9.1 后端

- 本地引擎单元测试：学科/年级/难度/分类推断、知识点提取、解析生成、空答案不臆造。
- Agent 规划器单元测试：各意图触发词、参数提取（学科/年级/数量/知识点）、未知意图降级。
- 题目领域测试：新字段校验、内容哈希稳定、AI 应用只允许草稿、权限与租户隔离。
- 集成测试（真实 PostgreSQL）：Agent 批量打标只改草稿；变式落库为草稿；审计日志写入；跨学校不可见。
- 模型客户端测试：使用 `httptest` 模拟 OpenAI 兼容响应、超时、非 JSON、降级路径；断言不泄露密钥。

### 9.2 前端

- Vitest：AI 响应 Zod Schema、目标参数序列化、运行状态渲染数据转换、编辑器建议应用逻辑。
- Typecheck、Lint、Production Build。
- 手动/浏览器验证：AI 工作台运行体检、编辑器分析与应用、题目列表展示新字段。

### 9.3 验收标准

1. 未配置模型密钥时，AI 工作台与编辑器助手可用，且明确显示“本地模式”。
2. 配置 OpenAI 兼容模型后，分析/变式/出题/体检使用大模型，失败自动降级。
3. Agent 能用一句中文完成“给数学草稿补标签和解析”并产生审计记录。
4. 任何已发布题目不会被 AI 自动修改。
5. 全量 Go 测试、`go vet`、前端 lint/typecheck/test/build 通过。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 模型生成错误答案 | 答案候选必须人工确认；本地模式不臆造选择题答案；生成题标记待复核 |
| 模型不可用/超时 | 本地降级 + 告警 + 明确 provider |
| 批量误改 | 仅草稿、单次上限、审计日志、逐题目标字段更新 |
| 提示注入 | 题干按数据隔离、输出白名单校验、不执行模型指令 |
| 成本失控 | 数量限制、截断、超时、后续配额 |
| 旧数据兼容 | 新字段全部默认值，哈希在体检时补算 |
| 结果不可追溯 | provider/model/confidence/时间与审计日志持久化 |

## 12. 明确不做

- 不让 AI 自动发布、归档、删除题目或管理账号。
- 不用 AI 结果替代教师最终审核。
- 不在前端保存或展示模型密钥。
- 不引入独立向量数据库/消息队列（本次规模不需要，避免过度设计）。

## 13. 补充：学校级共享模型配置

为方便管理员统一管理全校 AI 成本与密钥，新增学校级共享配置：

- 管理员在 `/admin/settings` 选择厂商（OpenAI、DeepSeek、通义千问、智谱、Moonshot 或自定义兼容接口），填写接口地址、API Key，勾选启用模型并设置默认模型。
- 配置按学校隔离，教师调用 AI 时自动使用本校配置；未配置时回退服务器环境变量，管理员停用时强制使用本地确定性引擎。
- API Key 使用 `AI_SETTINGS_SECRET`（缺省回退 `JWT_SECRET`）派生密钥进行 AES-GCM 加密存储，接口只返回掩码提示，绝不下发明文。
- 教师可在 AI 工作台从已启用模型中选择；`/ai/status` 返回可用模型、默认模型与配置来源，Agent 运行记录持久化实际使用的模型。
- 新增表 `school_ai_settings`，写入操作仅限管理员并记录 AI 审计日志。
